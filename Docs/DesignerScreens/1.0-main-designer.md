# 1.0 Main Designer

## Purpose
The primary working surface where users add widgets, bind data, and position overlay elements.

## Layout anatomy
- **Header**: Title, reset/save/publish, preview launcher.
- **Tools row**: Widget palette, grid/snap/safe-zone toggles, screen size chip.
- **Canvas**: 16:9 stage with optional grid, snap, and safe-zone overlay; widgets render here.
- **Footer (metadata explorer)**: Lists fields for the selected source/endpoint and shows latest payload/test response.

## Interactions
- Click a palette card → add widget with default size/position; new widget auto-selected.
- Palette is limited to Text, Image/GIF, and Marquee while we harden the data model.
- Click canvas background → clear selection.
- Drag/resize selected widget with Moveable; snap/grid optional.
- Double-click a widget → opens Widget Editor (1.1).
- Click Preview in header → opens Preview Modal (1.2).

## Data binding surface
- Binding happens in the Widget Editor modal (source → endpoint → field → format).
- Field options come from metadata (`ApiResponseMetadata.fields`) or typed models when available.
- Bound values resolve from the virtual data dictionary (`source|endpoint` payloads), currently populated via test calls.
- Plain text overlays render without chrome; styling and template text live in the editor.

## State persistence
- Save/Publish buttons POST serialized widget list to `/designer/layout?layoutId=default` (current single layout).

## Known gaps
- No undo/redo; no multi-select.
- Grid/safe-zone are CSS only; no pixel-perfect broadcast presets yet.
- No per-project switcher; single layout id in use.
